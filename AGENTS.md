# BloodLine — Agent Rules (single source of truth)

Emergency blood-request coordination app. Each request = one live group chat room
between requester, blood bank(s) and matched donors. Built for a 1-day hackathon on the
Nexconn Chat SDK.

## Stack
- App: Flutter (`app/`) with `ai_nexconn_chat_plugin` + `ai_nexconn_chatui_plugin`
- API: Go 1.22, stdlib `net/http`, SQLite (`modernc.org/sqlite`) (`api/`)
- Chat infra: Nexconn, Singapore data center (client SDK areaCode `AreaCode.sg`; server API https://api.sg-light-api.com). Server API is called only from `api/`, never from the app.

## Commands
- API run:   `cd api && go run ./cmd/server`   (listens on :8080)
- API test:  `cd api && go test ./...`
- App run:   `cd app && flutter run`
- App test:  `cd app && flutter test`
- Health:    `curl localhost:8080/health`

## Conventions
- API: JSON only, snake_case fields, errors as `{"error":"message"}` with proper HTTP status.
- API contract lives in docs/API.md. Change the doc FIRST, then the code. Never break it silently.
- Go: small packages under `api/internal/`, handlers thin, logic in services, no globals except config.
- Flutter: feature folders under `app/lib/features/<name>/`, state via `provider`, no business logic in widgets.
- Never commit secrets. Use `.env` (gitignored); keep `.env.example` current.
- Prefer the Chat UI package widgets (`ChannelPage`, `ChatPage`) over custom chat UI.
- Scope is frozen: see "Out of scope" in docs/PLAN.md. Do not add features.

## Multi-agent protocol (MANDATORY)
Two agents (OpenCode, Antigravity) work on this repo, ONE AT A TIME per working tree.
1. START: read docs/handoff/<agent>.md (opencode: api.md, antigravity: app.md) and docs/PLAN.md, run `git status` and `git log -10 --oneline`.
2. Work on the task named in HANDOFF.md "Next action" unless the human says otherwise.
3. Commit small and often. Prefix messages `[opencode]` or `[antigravity]`.
4. Never end a session with uncommitted work.
5. Tick/untick tasks in docs/PLAN.md as you start/finish them.
6. Log non-obvious decisions in docs/DECISIONS.md (append only).
7. END: run the handoff procedure; HANDOFF.md must be fully rewritten, under 60 lines.
8. Do not revert the other agent's commits without a DECISIONS.md entry.
9. Do not edit this file without human approval.
10. If a Nexconn API is unclear, check the docs / the `nexconn-chat` skill instead of guessing.
